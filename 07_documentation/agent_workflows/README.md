# agent_workflows

Records of the multi-agent runs used in this audit: the scripts that defined them and the results the agents returned. They are kept for two reasons. A machine reset loses everything that is not in git, and these runs take hours. And the verification of the audit's claims should itself be open to inspection.

Nothing here is part of the analysis pipeline, and no pipeline step reads these files.

## scripts/

Workflow scripts for the Workflow tool of Claude Code (JavaScript). Each defines the agents, their briefs, and how results pass between them. They are as launched, apart from one sentence reworded in `build-dml-sensitivity.js`.

| Script | What it does |
|---|---|
| `audit-verification.js` | Nine agents each try to refute one major claim of `issues.md` from the data. Six reviewers examine areas of the pipeline code, one of them by running steps 06 to 10 from a clean clone. Each reviewer's findings are re-examined by a second agent. Read-only on the repository. |
| `build-steps-11-12.js` | Builds pipeline steps 11 (semantic similarity) and 12 (qPCR): one agent writes the step, a second reviews it independently, a third fixes what the review confirmed. |
| `manuscript-values.js` | For a list of manuscript sections given as `args`: one agent lists every quantitative statement, a second ties each to an R expression over the pipeline outputs and tests it, a third recomputes each value independently and looks for missed statements. The rows it returns become `03_input_files/manuscript/manuscript_values_map.csv`. |
| `build-dml-sensitivity.js` | Builds `06_diagnostics/dml_sensitivity.R` (overdispersion, tested interaction, without the four acute heat-shock libraries, within-cohort contrasts) on a subset of CpGs, with independent review and fixes. The full model fits are run separately. |
| `check-issues-integration.js` | After the nine claim reports of `audit-verification.js` were written into `issues.md`: one agent per report checks that every error and caveat it reported was carried in without distortion, and a tenth checks consistency across `issues.md`, the READMEs, the plan and code comments. Read-only on the repository. |
| `build-diagnostics.js` | Turns five computations of the verifying agents into scripts under `06_diagnostics/` that run from the repository (matched and label-permuted odds ratios of DML by genome feature; the locus on NC_047563.1; the mechanism of the file-reading fault; variants of the coverage filter; equivalence of the low-memory import with methylKit's own). One agent writes each, a second reviews it independently, a third fixes what the review confirmed. |
| `check-sensitivity-text.js` | After the sensitivity analyses were written into `issues.md` (I-06 rewritten, I-49 added, five issues updated): five agents, each instructed to refute. S1 recomputes I-06 from the cached fits and tests its readings on relabelled libraries; S2 does the same for I-49 with eight alternative explanations; S3 reviews `06_diagnostics/library_methylation_level.R`; S4 checks the five smaller updates and every other file that repeats them; S5 checks the citations. Read-only on the repository. |
| `check-literature-additions.js` | After the check of the citations (S5 of `check-sensitivity-text.js`) had added about thirty published sources to `issues.md`: three second readers, by topic (statistics and methods; mitochondrial DNA and library preparation; oyster biology and triploid production), each instructed to refute the new statements against the sources themselves, to check every quotation and number, and to look for published work that contradicts them. Read-only on the repository. |
| `pipeline-hardening.js` | Launched on 2026-11-19 at 21:20 UTC from commit `24ff5d1`. The pass that fixes the confirmed findings of the six code reviews, narrowed on 2026-11-19 by the author's scope decision to defects of the pipeline code and of its documentation: three agents by pipeline area (steps 04 and 05; 06 and 07; 08 and 09), one for the shared code, then a rerun of the whole pipeline that explains every changed output, two reviewers and a repair stage. No analysis is changed; step 10, corrected mode and the scripts of `06_diagnostics/` are not touched. Its inputs are under `code-pass-inputs/`: the findings sorted by area are regenerated by `make_codepass_findings.py`, `extra_items.txt` holds the further tasks in scope, and `deferred_items.txt` holds what was planned before the scope decision and is not to be done without the author's approval. |
| `manuscript-values-batch2-args.json` | The `args` of the second run of `manuscript-values.js` (Results 3.4 and 3.5, Table 1, Discussion), with the note that tells the agents which outputs of steps 11 and 12 and of `06_diagnostics/` to use. |
| `eval_expressions.R` | Evaluates candidate expressions for the manuscript values map the way step 13 does; used by the agents of `manuscript-values.js`. |

To run one again in a new session, edit the constants at the top of the script: `SCRATCH` (any scratch directory) and `MANUSCRIPT` (a plain-text copy of the manuscript draft with one paragraph per line, exported from the Google Doc linked in the root README; the copy is not in the repository, by decision of the author, and `03_input_files/manuscript/README.md` records the one that was used; `manuscript-values.js` refers to its line numbers, so the section line ranges in that script must be checked against the copy). `manuscript-values.js` also expects a catalog of output tables at `SCRATCH/output_catalog.txt` (one line per table of `04_output/*/tables` with its column names) and `eval_expressions.R` in `SCRATCH`.

## results/

One JSON file per run, holding what each finished agent returned (`agent`, `phase`, `result`) and the names of agents that had not finished when the file was written. The files are rewritten as agents finish. They are raw reports: a claim marked "confirmed" or a finding marked "high" is one agent's conclusion until it has been checked and carried into `issues.md`, the code, or the manuscript values map. Once a run has been integrated, its file stays as the record of what was reported.
