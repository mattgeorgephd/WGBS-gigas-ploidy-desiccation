# 01_pipeline

The analysis, as numbered R scripts that run in order. Each script reads the inputs in `03_input_files/` and the outputs of earlier steps in `04_output/`, and writes only into its own folder `04_output/<step>/`, with two exceptions: step 01 (and step 09, if step 01 was skipped) fills the download cache, and step 13 writes `05_manuscript/`. That is the paper run. An optional run (section Run kinds and optional analyses) writes only under `04_output/not_adopted/` and `05_manuscript/not_adopted/`. The unnumbered script `optional/ct_variant_loci.R` makes the C-to-T variant list of the option `--exclude-ct-variants` and is run by hand ([`optional/README.md`](optional/README.md)).

For the project overview see the [root README](../README.md); for the design and the order of work see [`07_documentation/reproducibility_plan.md`](../07_documentation/reproducibility_plan.md).

## Run kinds and optional analyses

A run with no optional setting on is the **paper run**: steps 01 to 09, 11 (paper part), 12 and 13 (paper part), writing the paper's outputs in `04_output/<step>/` and `05_manuscript/` and nothing else. Any switch makes an **optional run**, which never writes into a paper folder (`output_dir()` of `02_R_functions/paths.R` stops it): steps 04 to 09 for the optional analysis, 10 and 11 (gene-level part) with `--gene-level-go`, the diagnostics with `--diagnostics` (after step 11), and step 13 (optional part). Steps 01 to 03 and 12 do not depend on the analysis and belong to the paper run only; started alone in an optional configuration, a step that has nothing to do says so and ends with status 0. Every step prints the run kind and the analysis under its banner, and `run_pipeline.R` prints the plan at the start (`--plan` prints it alone) and the run kind and analysis at the end.

|---|---|---|---|---|---|---|---|

The two readings of the coverage files:

| Reading | Coverage filter | Coverage files |
|---|---|---|
| the paper (`legacy`) | No upper filter: the legacy call misnamed the argument, so the filter never ran (issue I-05) | First line of each file lost, as in the legacy import (issue I-38) |
| option `corrected` | CpGs at or above the 99.9th percentile of coverage in a library are removed from that library, as the Methods describe | Every line read |

The analysis of a step started alone is chosen by three environment variables, which `run_pipeline.R` sets for its steps and refuses to find already set: `WGBS_ANALYSIS` (an id, for example `WGBS_ANALYSIS=cov5-mnchisq Rscript 01_pipeline/05_differential_methylation.R`), `WGBS_GENE_LEVEL_GO` (`TRUE` or `FALSE`) and `WGBS_DIAGNOSTICS` (`none`, `all` or names joined by commas). An empty or unknown value stops the step. Each analysis folder carries a stamp (`analysis.csv`): step 04 writes it, every later step adds itself and stops if the stamp describes another analysis or a step it reads from has not run for it. Step 05 keeps one fit per fit id (`cache/methylkit_<fit id>.rds`, the id without `ctexcl`): an analysis with `ctexcl` reuses the fit of the same analysis without it and removes the listed CpGs after the test, so its p-values and q-values are those of the fit on all CpGs, as in Venkataraman et al. 2022.

Step 10 is not part of the paper run. Started alone without `WGBS_GENE_LEVEL_GO=TRUE`, it says so and ends with status 0; with it, it runs for the analysis of `WGBS_ANALYSIS` (the paper's DML when unset) and writes under `04_output/not_adopted/<id>/`.

## How a step is written

1. A header block states the purpose, the inputs with their locations, the outputs, and the manuscript items the step is responsible for.
2. The step sources `run_config.R` and every file in `02_R_functions/`, and loads its packages through one helper, so a missing package is reported by name before any work starts. The helper also asks for R.utils whenever a step names data.table, because `fread()` reads the `.gz` tables through it. `run_config.R` checks the settings of the analysis as it is sourced, so such a setting that cannot work stops the step at this point too (its header names the settings it does not check).
3. All paths are built with `here::here()`. There is no `setwd()`, no `rstudioapi`, and no absolute path. A script runs the same from RStudio (Source) and from a terminal (`Rscript 01_pipeline/05_differential_methylation.R`).
4. Sample groups come from `03_input_files/metadata/wgbs_libraries.csv`, never from positions in a list.
5. No number is typed into a script and no spreadsheet is edited between steps. Settings are in `run_config.R`, with one list for a step that has many (`semantic_similarity` for step 11, `qpcr` for step 12).
6. The paper's analysis is the default. An analysis that the paper did not adopt is an option, off by default, with a switch of `run_pipeline.R` and a setting in the list `optional` of `run_config.R`; the step writes its outputs through `analysis_path()` into `04_output/not_adopted/<id>/<step>/`, with the analysis id in the file names where the paper's names carry `legacy`.
7. The step ends by writing its session information to `04_output/<step>/session_info.txt` (in an optional run, to the step's folder under `04_output/not_adopted/`).

## Running

```sh
Rscript run_pipeline.R                   # all steps in order
Rscript run_pipeline.R --steps 5:7       # steps 05, 06 and 07
Rscript run_pipeline.R --steps 2:3,6:10  # steps 02, 03 and 06 to 10
Rscript run_pipeline.R --list            # show the steps and exit
Rscript run_pipeline.R --coverage-filter --overdispersion   # an optional analysis: not_adopted/corrected-mnchisq/
Rscript run_pipeline.R --plan --coverage 5 # print the plan of a run and exit
```

or source an individual script in RStudio with the project (`WGBS-gigas-ploidy-desiccation.Rproj`) open.

`run_pipeline.R` can be started from any working directory: it takes the repository to be the folder it lies in and starts each step there. It reads and checks `run_config.R` before the first step, stops at the first step that fails, and ends with a table of the steps, their minutes and their result. The selection after `--steps` is one word without spaces; a selection it cannot read (`--steps 3, 12`, an empty selection, a second `--steps`, a range that runs downward, a step that does not exist) stops the run before any step starts. A single step is started with the working directory inside the repository (`Rscript 01_pipeline/12_qpcr.R`); see How paths work in the root README.

Steps 04 and 05 need the 22 coverage files and the reference genome (10.5 GB, downloaded once by step 01), and about 9.5 GB (step 04) and about 10 GB (step 05 with `WGBS_CORES=4`) of memory. Step 05 keeps its model fits in `04_output/05_differential_methylation/cache/` (one per fit id) and reuses a fit only while the settings, the model, sample sheet, coverage files, methylKit version and fitting code it was made from are unchanged; otherwise it fits again. The paper's fit is made in one piece (and reused by `ctexcl`). Every other optional analysis is fitted by sequence (decision of the author, 2026-11-20): the import and the united table are made genome-wide and saved, then the tests are run one part of the genome at a time (each linkage group, and the other sequences in groups of at most 50,000 CpGs), and each finished part is saved in `cache/parts_<fit id>/`; the SLIM q-values are computed once over all CpGs when every part is in. A run that is stopped loses only the part it was fitting: start the same command again and it goes on from the saved parts, after stopping any leftover process of the run (`pgrep -af 05_differential`; a lock in the parts folder stops a second run while the first lives) (the log says, part by part, which were reused and which were fitted, with the time and the peak memory of each). The results are identical to a fit in one piece (`tests/check_fit_by_sequence.R`: p-values, q-values and differences identical, not merely close, for the paper's analysis and `mnchisq` at 10x). An optional analysis also takes a cached fit made in one piece from the same inputs and code, so the fits of `mnchisq`, `corrected` and `corrected-mnchisq` made before 2026-11-20 are still used. The version of R and of the other packages is not compared: after an upgrade of R, delete that folder so that the fits are made again. Every later step runs from files that are in the repository, except that step 09 also needs the GO.db 3.13.0 package (31 MB, fetched from the Bioconductor archive into the cache by step 01, or by step 09 itself if step 01 was skipped).

Besides the three variables of the optional analyses (above), two environment variables are read by `run_config.R`: `WGBS_CACHE_DIR` (where downloads are kept; default `03_input_files/gannet_cache/`) and `WGBS_CORES` (cores for the model fits of step 05; default 1). `WGBS_CORES` must be a whole number of 1 or more; set to anything else, an empty value included, it stops every script at once. On Windows leave it unset: the fits fork their workers, which Windows cannot do, and a larger value is replaced by 1 with a message.

Steps 09 and 10 load different releases of GO.db and must not share an R session; `run_pipeline.R` starts each step in a fresh process, and both steps stop with a message if the wrong release is already loaded. Step 11 uses the GO.db of the R installation, as step 10 does, and stops if the legacy release is loaded; it checks that the outputs it reads exist before it starts (steps 08 and 09 in the paper run; step 10 of the analysis in the gene-level part).

No step reads `08_archive/`. The legacy files that steps 11 and 12 redraw or compare with are copies under `03_input_files/`: the REVIGO exports and three Fisher tables of another analysis in `annotation/legacy/revigo_exports/` and `annotation/legacy/fisher_other_analysis/` (step 11), and the knitted legacy qPCR output in `qpcr/legacy/` (step 12). The README of each folder says where a file came from. The checks in `06_diagnostics/` do read the archive.
