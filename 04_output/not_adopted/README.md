# 04_output/not_adopted

**Nothing in this folder is a result of the paper.** It holds the outputs of the optional analyses that the paper did not adopt. The paper's outputs are in `04_output/<step>/` and `05_manuscript/` outside the folders named `not_adopted`: a path that contains `not_adopted` is not the paper's.

Each optional analysis is off by default. It is turned on by a switch of `run_pipeline.R` or by a setting of `run_config.R` (list `optional`); the switches combine. One run computes one analysis, named by its id: the tokens of the switches that are on, in the order `corrected`, `cov5`, `mnchisq`, `ctrl` or `inter` (not both), `ctexcl`, `d50`, `q05`, joined by `-` (192 ids, `legacy` being the paper's). `Rscript run_pipeline.R --plan <switches>` prints what a run would do.

Examples:

```sh
Rscript run_pipeline.R                                                       # the paper, nothing else
Rscript run_pipeline.R --coverage-filter                                     # -> not_adopted/corrected/
Rscript run_pipeline.R --overdispersion                                      # -> not_adopted/mnchisq/
Rscript run_pipeline.R --overdispersion --difference 50                      # -> not_adopted/mnchisq-d50/ (reuses the fit of mnchisq)
Rscript run_pipeline.R --qvalue 0.05 --difference 50                         # -> not_adopted/d50-q05/ (reuses the paper's fit)
Rscript run_pipeline.R --controls-only-ploidy                                # -> not_adopted/ctrl/ (ploidy on the 12 controls; heat from the paper's fit)
Rscript run_pipeline.R --overdispersion --interaction --qvalue 0.05          # -> not_adopted/mnchisq-inter-q05/ (fit mnchisq-inter on the fit of mnchisq)
Rscript run_pipeline.R --coverage-filter --overdispersion --gene-level-go    # -> not_adopted/corrected-mnchisq/, with steps 10 and 11
Rscript run_pipeline.R --gene-level-go                                       # step 10 on the paper's DML -> not_adopted/legacy/
Rscript run_pipeline.R --diagnostics cohort_separation                       # one script of 06_diagnostics/
Rscript run_pipeline.R --plan --coverage 5 --exclude-ct-variants             # print the plan only
WGBS_ANALYSIS=mnchisq Rscript 01_pipeline/05_differential_methylation.R      # one step alone, for one analysis
```

## Layout

```text
04_output/not_adopted/
  README.md                           this file
  <id>/                               one optional analysis, for example corrected/, mnchisq/, corrected-mnchisq/
    analysis.csv                      stamp: settings of the analysis, md5 of its fit and of the variant list, commit, time, steps done
                                      (step 04 removes it and the folders of steps 05 and later before it writes; a table
                                      counts, in step 13 and in comparisons/, only while the stamp lists its step)
    04_cpg_coverage/ ... 09_go_enrichment_legacy/    the files of the paper's steps, <id> in place of "legacy" in the names
                                      (dml_ploidy_mnchisq.csv, figure_2_mnchisq.png); the paper's names without a mode keep their names
    10_go_enrichment_gene_level/      only with --gene-level-go
    11_semantic_similarity/           only with --gene-level-go: the gene-level part
  legacy/                             --gene-level-go on the paper's DML: steps 10 and 11 (gene level) only
  ct_variants/                        the C-to-T variant list of 01_pipeline/optional/ct_variant_loci.R (tables/; cache/ is not tracked)
  comparisons/                        the tables that list analyses side by side, rebuilt by every optional run from every
                                      analysis folder on disk, the paper first; analyses_included.csv lists the stamps used
  13_manuscript_values/tables/        expression_errors_by_analysis.csv, manuscript_items_copied.csv of the optional part of step 13
```

Rules that keep the paper's outputs safe: an optional run never opens a file of a paper folder for writing (`output_dir()` of `02_R_functions/paths.R` stops such a run, except for the git-ignored `cache/` folders), and the paper run never writes here. In an optional run the steps that do not depend on the analysis (01 to 03 and 12) are not started, and the tables of step 04 and step 08 that only the paper run writes (`library_coverage.csv`, `genome_cpg_total.csv`; `gene_go_map.csv.gz`, `transcript_table.csv.gz`, `go_map_id_repair.csv`) are read from the paper folder and not written again. They do not depend on the analysis, with one exception: under `ctexcl` the libraries lose the listed CpGs, so the analysis's own `library_coverage.csv` would differ (CpGs per library, first line, medians, cutoffs); it is not written, and step 13 reads the paper's for every analysis.

Column `mode` of every table holds the analysis id (the paper's tables keep the value `legacy`).

### The option `d50`

Author's decision of 2026-11-21: "The 2022 paper also used a 50% cut off. All variations of the runs should also be run with this cutoff as well as the 20% I use in the paper." Venkataraman et al. 2022 (BMC Genomics 23:556) called DML with methylKit `getMethylDiff` at `difference = 50` and q < 0.01. With `--difference 50` step 05 keeps the CpGs with q < 0.01 and an absolute difference of more than 50 points (strict, as `getMethylDiff` applies it); the paper's setting `dml_difference = 20` of `run_config.R` stays frozen, and the paper's run never changes. `--difference 20` names the paper's value and does not turn off `dml_difference_standard = 50L` set in `run_config.R` (the same rule as `--coverage 10`).

- **Fit.** The threshold is applied after the test, so a `d50` analysis reuses the fit of its analysis without `d50` (for `d50` itself the paper's fit, `methylkit_legacy.rds`); nothing of the threshold enters the fingerprint of a fit.
- **Step 04** of a `d50` analysis is that of its analysis without `d50` (same CpG sets), run again under its own id: 7 to 9.5 minutes and up to 9.2 GB at 10x. A `d50` run must therefore not run beside a 5x fit.
- **What changes besides the DML lists.** The "eligible" CpGs of steps 07, 08 and 10 (mean methylation from half the threshold to 100 minus that: 25% to 75% at 50 points, 10% to 90% at 20; with the paper's fit 30,315 of 480,579 CpGs, 6.3%, at 50 points against 65,480, 13.6%, at 20), and in step 13 the value of `config$dml_difference` in the expressions of both recipes (50), so the statements that name the threshold of 20 points, or apply it to group means, are evaluated at 50. `dml_counts_by_threshold_<id>.csv` (5 to 50 points) is the same as that of the analysis without `d50`.
- **Few or no DML.** At 50 points the lists are short (with the paper's fit: 1 ploidy DML, 4 heat DML, no locus in both lists). Steps 06 to 10 then write their tables with their columns and the rows there are, and replace a panel that cannot be drawn with a note. Step 09 does not run the Fisher test of a set without a transcript of interest in the legacy universe, and step 10 does not test a set none of whose DML genes carries a term of the ontology; both log it and write the set's tables without rows. Step 13 evaluates the statements as for any other analysis: a value about a locus or gene not in the lists is "not comparable: no value in this analysis", and an expression that fails because a DML set is too small is "not evaluable: too few DML (<message>)" (column `not_evaluable` of the summary), not an error. A set is too small when it has fewer than 2 DML in `dml_counts_by_mode.csv` of the analysis, or when step 09 could not test it (its Fisher table has no row); the expression must have read a table of that set (or, when every set has fewer than 2 DML, any table of steps 05 to 10 of the analysis). An expression that read `go_gene_level_<set>_<id>.csv` of a set step 10 did not test (no row) is not evaluable even when it gives a value. No error message is matched, so a failure with another cause in such an expression is also counted as not evaluable: its message is kept in the status and in `04_output/not_adopted/13_manuscript_values/tables/expression_errors_by_analysis.csv` (column `state`: `error` or `not evaluable: too few DML`), and step 13 logs the count of such statements on a line of its own. In `legacy_top10_at_gene_level.csv` (step 10) and `named_terms_results_3_4_gene_level.csv` (step 11) a term of an untested set has the status "set not tested: no DML gene carries a term of the ontology". Statements that read only `go_gene_level_summary.csv` (for example R3.4-007, "no term of the ploidy set is enriched") cannot be told apart and keep their value. Tested on 2026-11-21 in a scratch copy: `d50` and `mnchisq-d50` have 8 such statements under the paper recipe (R3.2-029 and R3.2-031, clusterings that need 2 loci; F6-002, F8-002 and D4.1-003, -005, -007, -010, which look up GO terms in Fisher tables without rows) and 2 under the corrected recipe (R3.2-029, R3.2-031); with `--gene-level-go` the corrected recipe of `d50` has 33, the 31 more reading the step 10 tables of the ploidy and shared sets, which step 10 did not test. None is an error; real errors (as the two of `cov5`, I-51) stay errors. With an unrelated fault injected into two statements that read tables of the ploidy set (an unknown object), the analyses at 20 points report it as an error and the `d50` analyses as not evaluable, both with the message `object '...' not found`.

### The option `q05`

Author's request of 2026-11-22: run the variations at a DML q-value cutoff of 0.05 as well as at the paper's 0.01. With `--qvalue 0.05` step 05 keeps the CpGs with a SLIM q-value below 0.05 (strict, as methylKit `getMethylDiff` with `qvalue = 0.05` applies it) and an absolute difference of more than the threshold of the analysis (20 points, or 50 with `d50`); the paper's setting `dml_qvalue = 0.01` of `run_config.R` stays frozen, and the paper's run never changes. `--qvalue 0.01` names the paper's value and does not turn off `dml_qvalue_standard = 0.05` set in `run_config.R` (the same rule as `--coverage 10` and `--difference 20`). The token `q05` is the last of an id: `q05`, `mnchisq-q05`, `d50-q05`, `corrected-cov5-mnchisq-ctexcl-d50-q05`.

- **Fit.** The q-values are those of the fit (SLIM over all tested CpGs of the analysis), and the cutoff is applied after the test, so a `q05` analysis reuses the fit of its analysis without `q05` (for `q05` and `d50-q05` the paper's fit, `methylkit_legacy.rds`); nothing of the cutoff enters the fingerprint of a fit, and the paper's fingerprint is unchanged.
- **Step 04** of a `q05` analysis is that of its analysis without `q05` (same CpG sets), run again under its own id, as for `d50`.
- **What changes besides the DML lists.** `dml_counts_by_threshold_<id>.csv` (5 to 50 points), and so panels A and B of Figure 2, are counted at q < 0.05. The eligible CpGs of steps 07, 08 and 10 depend on the difference threshold only and are those of the analysis without `q05`. In step 13 `config$dml_qvalue` is 0.05 in the paper recipe (the corrected recipe has no expression for these two rows), so the two statements that name the cutoff of 0.01 (M2.5-005 and R3.2-007) give 0.05 and differ from the manuscript. The stamp `analysis.csv` has a column `dml_qvalue` after `dml_difference` (a stamp written before the option existed reads as 0.01), and the comparison table below has a column Q.
- **More DML.** A list at q < 0.05 holds every DML of the same analysis at q < 0.01. Tested on 2026-11-22 in a scratch copy, with the paper's fit from the cache: `q05` has 1,038 ploidy and 2,352 heat DML and 201 loci in both lists (the paper: 1,038, 2,351 and 200), and `d50-q05` the same 1 ploidy and 4 heat DML as `d50`, no locus in both lists. At 20 points and more the q-value of a CpG that passes the threshold is almost always far below 0.01, so the cutoff changes the lists little; below 20 points it matters (at 10 points 7,678 ploidy and 13,805 heat DML at q < 0.05 against 5,352 and 10,747 at q < 0.01, `dml_counts_by_threshold_q05.csv`). In step 13 `q05` has no error and no statement that is not evaluable, and `d50-q05` the same 10 not evaluable statements as `d50`.

### The option `ctrl`

Author's request of 2026-11-22 (issue I-07): the text of the draft describes the ploidy differences as baseline differences, under control conditions, but the paper's ploidy contrast uses all 22 libraries with heat as covariate. With `--controls-only-ploidy` (setting `contrast_variant = "ctrl"` of `run_config.R`) step 05 tests ploidy on the 12 control libraries alone: the 6 diploid against the 6 triploid controls, without covariate (all are controls), with the methylKit test of the analysis (with `mnchisq`, overdispersion "MN" and the chi-squared test). The CpGs are those of the analysis (the coverage filter applied over all 22 libraries) with its normalisation; the test uses the 12 control columns of that united table, and its SLIM q-values are computed over all of its CpGs. The difference is triploid minus diploid among the controls. The ploidy DML list of the analysis is this list, the heat list is that of the analysis without `ctrl`, and the shared set is the overlap of the two; steps 06 to 13 treat the analysis as any other. The token comes after `mnchisq` and before `ctexcl` (`ctrl`, `mnchisq-ctrl`, `corrected-cov5-mnchisq-ctrl-ctexcl-d50-q05`), and it cannot be combined with `inter` (the switches given together stop the run before a step starts).

- **Fit.** The fit id keeps the token (`ctrl`, `cov5-mnchisq-ctrl`). Step 05 takes the fit of the analysis without `ctrl` (its base fit; for `ctrl` the paper's `methylkit_legacy.rds`) exactly as that analysis takes it, under its own, unchanged fingerprint, and fits only the control-only ploidy contrast, by sequence and resumable (`cache/parts_<fit id>/`). A new `ctrl` fit therefore takes about half the time of a fit (estimated: 12 minutes at 10x and 45 at 5x at `WGBS_CORES=2`), plus the base fit when it is not in the cache. The heat contrast is that of the base fit. `methylkit_<fit id>.rds` holds the new contrast only (p-values and differences, no copy of the united table); its fingerprint holds the key of the base fit's fingerprint, the library sheet, the design, the model, the methylKit version and the code of the new contrast, so a base fit made again refits it. No fingerprint of an existing fit changes (the code of the existing fits is that of commit 76a900b; `tests/check_settings.R` checks it).
- **Comparable with the diagnostic.** The test is that of analysis `A4_ploidy_in_control` of `06_diagnostics/dml_sensitivity.R` (`A4_ploidy_in_control_mn_chisq` with `mnchisq`), which at the paper's settings lists 2,768 DML (2,211 hyper, 557 hypo) of 480,579 CpGs, and 10 with the correction (`06_diagnostics/dml_sensitivity/dml_counts.csv`). `tests/check_contrast_variants.R` checks on simulated counts that the fit by sequence gives the p-values, q-values and differences of that call on the whole table, to the last bit. After a run of `ctrl` or `mnchisq-ctrl`, `Rscript tests/check_contrast_variants_real.R <id>` compares its tables with those of the diagnostic (it reads the diagnostic's cached fits, which are not tracked).
- **Stamp and comparison.** The stamp `analysis.csv` has a column `contrast_variant` after `test` (`none`, `ctrl` or `inter`; a stamp written before the options existed reads as `none`). The comparison table has a column Contrasts and lists the `ctrl` analyses after those with the paper's contrasts.

### The option `inter`

Author's request of 2026-11-22 (issue I-02): the shared set (the legacy "interaction-DML") is an overlap of two main-effect lists, not a test of interaction. With `--interaction` (setting `contrast_variant = "inter"`) step 05 adds a tested ploidy by heat interaction: the indicator "triploid and heat-treated" tested with ploidy and heat as covariates on all 22 libraries, with the methylKit test of the analysis. With both main effects in the null model the full model has one parameter per group, so this test is the test of the interaction; step 05 checks the coding against the model ploidy * heat, and `tests/check_contrast_variants.R` compares its p-values with the likelihood ratio test of a binomial model written that way. The effect size is (triploid heat minus triploid control) minus (diploid heat minus diploid control), from the pooled, coverage-weighted percentages of the four groups, as analysis `A2_interaction` of `06_diagnostics/dml_sensitivity.R` computes it; methylKit's difference for this coding (triploid heat minus all other libraries) is not used. A positive value ("hyper") means that heat minus control is higher in triploids than in diploids. Heat is confounded with cohort (I-01), so this is a ploidy by cohort interaction. The token comes after `mnchisq` and before `ctexcl` (`inter`, `mnchisq-inter-q05`), and it cannot be combined with `ctrl`.

- **Outputs.** Step 05 writes `diffmeth_interaction_<id>.csv.gz` (p, q, the interaction difference in the column `meth.diff`, and the percentages of the four groups), `dml_interaction_<id>.csv` by the DML rule of the analysis (q cutoff and difference threshold; with `ctexcl` the listed CpGs leave it too, and `ct_exclusion_summary_<id>.csv` has a row `interaction`), `bed/dml_interaction_<id>.bed`, and four columns at the end of `dml_counts_by_mode.csv`: `interaction_dml`, `interaction_hyper`, `interaction_hypo` and `interaction_in_shared` (the interaction DML among the shared loci). The ploidy and heat lists and the shared set are those of the analysis without `inter`. Steps 06 to 13 do not use the interaction list. The tables of the paper and of every analysis without `inter` keep their columns; in `comparisons/05_differential_methylation/tables/dml_counts_by_mode.csv` their rows have empty fields in the four columns (`rebuild_comparison()` adds them; without an `inter` analysis the table is as before).
- **Fit.** As for `ctrl`: the fit id keeps the token, the base fit (with the ploidy and heat contrasts) is taken from the cache under its own fingerprint, and only the interaction is fitted, by sequence and resumable (estimated: 12 minutes at 10x and 45 at 5x at `WGBS_CORES=2`).
- **Comparable with the diagnostic.** At the paper's settings `A2_interaction` lists 16,971 DML (1,746 hyper, 15,225 hypo), 99 of them among the 200 shared loci, and `A2_interaction_mn_chisq` 242; with the coverage filter (`corrected`) 16,257 and 231 (`06_diagnostics/dml_sensitivity/dml_counts.csv`, `interaction_vs_shared_<mode>.csv`). The interaction contrast has four groups of 5 or 6 libraries, so many CpGs pass the difference threshold by chance; the permutation reference of the diagnostic shows how many. After a run of `inter`, `mnchisq-inter`, `corrected-inter` or `corrected-mnchisq-inter`, `Rscript tests/check_contrast_variants_real.R <id>` compares its tables with those of the diagnostic.

## Comparison of all analyses

`Rscript 01_pipeline/optional/compare_analyses.R` (from the repository root) writes `comparisons/analysis_comparison.csv` (every count, rates per 1,000 tested CpGs, ratios to the paper, counts at 10, 15 and 25 points and a column `venkataraman_2022_settings`) and `comparisons/analysis_comparison.md` from the tables every run writes; it computes nothing new from the data. After a new run, run the script again; the file is authoritative, and no copy of it is kept here. Only `legacy` is the paper's analysis. A DML has a SLIM q-value below the cutoff of its row (column Q: 0.01 in the paper, 0.05 with option `q05`) and an absolute difference of more than the threshold of its row (percentage points). Upper filter: the 99.9th percentile coverage filter that the draft describes but did not apply (I-05). Shared: loci in both lists; opposite: different directions in the two lists. V2022: the settings that the Methods of Venkataraman et al. 2022 (BMC Genomics 23:556) state for coverage, the test, variant removal and the threshold, at q < 0.01; the variant rule counts reads with their full CIGAR (I-08).

As of 2026-11-24 the table has 192 rows: the 64 combinations of the six settings that do not change the contrasts (`corrected`, `cov5`, `mnchisq`, `ctexcl`, `d50`, `q05`, each on or off; the paper's settings are the one with all six off), each with the paper's contrasts, with `ctrl` and with `inter`. In brief (issues.md, I-02, I-07, I-51 and I-52):

| Contrasts | Without the overdispersion correction, 20 points | With the correction, 20 points | At 50 points |
|---|---|---|---|
| The paper's (64 analyses) | ploidy 635 to 1,038 DML at 10x, 6,902 to 10,335 at 5x; heat 1,596 to 2,352 and 15,376 to 21,604; shared 100 to 201 and 1,148 to 1,891 | ploidy 12 to 37 and 96 to 321; heat 118 to 410 and 875 to 2,834; shared 4 to 6 and 19 to 45 | ploidy 1 to 6, heat 2 to 92; no shared locus |
| `ctrl` (64) | control-only ploidy 1,985 to 3,326 at 10x, 14,741 to 27,725 at 5x, 77% to 84% higher in triploids; heat as the paper's | control-only ploidy 5 to 53 and 106 to 398; shared with the heat list in 2 of 16 analyses, one locus each | control-only ploidy 0 to 50; no shared locus |
| `inter` (64) | ploidy, heat and shared as the paper's; interaction 13,282 to 20,352 at 10x, 70,041 to 112,438 at 5x, 86% to 91% negative; 26% to 56% of the shared loci among them | interaction 194 to 2,006 and 1,427 to 9,044, 92% to 95% negative; none of the shared loci among them | interaction 61 to 7,876 (a difference of two differences, not on the scale of a main effect) |

Each cell of the two 20-point columns covers 16 analyses (10x and 5x, each with and without the upper filter, `ctexcl` and `q05`), and each cell of the 50-point column 32 (with and without the correction as well); where two ranges are given, the first is at 10x and the second at 5x. Whether these lists are longer than relabelled libraries give was at first checked only at the paper's settings (10x, q < 0.01, without the upper filter and the exclusion): for the control-only list by its length, with and without the correction, and for the corrected interaction by its share of small p-values (issues.md, I-06 item 2, I-02 and I-07). At 5x it has been checked for the corrected lists of `cov5-mnchisq-ctrl` and `cov5-mnchisq-inter` (`06_diagnostics/dml_corrected_test_5x.R`): the control-only list is of the length that regroupings give, the interaction list longer than any relabelling gives. Since 2026-11-25 every corrected control-only and interaction analysis has been checked (`06_diagnostics/dml_corrected_test_settings.R`): all 32 control-only lists are of chance length, all 32 interaction lists longer than relabelled lists, and the one interaction list tested without the five libraries of I-49, `cov5-mnchisq-inter`, rests mostly on them (`06_diagnostics/interaction_high_libraries_5x.R`).

## What is tracked

An optional analysis commits its results, not its tables of every tested CpG. For every analysis folder except `corrected/`, `05_differential_methylation/tables/united_cpg_<id>.csv.gz` and `diffmeth_<contrast>_<id>.csv.gz` (13 to 22 MB each at 10x, up to 98 MB at 5x) are git-ignored (decision of 2026-11-20, pending the author). Rerun step 05 for the analysis to make them again: `WGBS_ANALYSIS=<id> Rscript 01_pipeline/05_differential_methylation.R` (half a minute with the fit in the cache, else 22 to 24 minutes); steps 06 to 08 stop with that command when the united table is absent. Step 05 writes `united_at_dml_<id>.csv`, the rows of the united table at the DML of either list (tracked), and step 13 reads that, so the optional values in `05_manuscript/not_adopted/` are reproduced from a clone. `gene_table_<id>.csv.gz` (step 08) and `ct_excluded_cpgs_<id>.csv.gz` (step 05, `ctexcl`) stay tracked. The per-CpG tables of `corrected/` predate the settings layout and are read by seven scripts of `06_diagnostics/` (column `reads_corrected_files` of `06_diagnostics/diagnostics.csv`); they stay tracked.

The values of the manuscript for every analysis are in `05_manuscript/not_adopted/manuscript_values_by_analysis.csv`, written by step 13 in an optional run, with "not run" for the analyses that have no folder. The paper's analysis has no rows there (its values are in `05_manuscript/manuscript_values.csv`). Each statement has two values (decision of the author, 2026-11-20). The main columns (`regenerated`, `differs_from_manuscript`, `status`) are the paper recipe: the paper's own computation (`expression_legacy`) applied to the tables of the analysis, through the template `expression_paper_recipe` of the values map, so that a difference from the paper's value comes only from the option; with `A = "legacy"` every template gives the paper's value (`tests/check_paper_recipe_legacy.R`). The columns ending in `_corrected_recipe` are the corrected recipe: the template `expression_optional`, the former corrected-mode expression with `A` in place of `corrected`, which for some rows is a corrected definition of the quantity or another column (applied to the paper's own outputs it differs from the paper's value in 56 of 263 rows). `05_manuscript/README.md` describes both and the rows that needed more than a change of file name.
