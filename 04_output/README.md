# 04_output

Results written by the pipeline. Nothing here is edited by hand; every file is regenerated by the script named in its folder.

## Layout

```text
04_output/
  <step>/                 one folder per script in 01_pipeline/, named after the script, for example 05_differential_methylation/
    tables/               CSV (gzipped when large)
    figures/              PNG and PDF panels
    session_info.txt      R and package versions of the run that wrote the folder
```

## What is tracked

Files up to 50 MB are committed, so every later step, and every reader of the manuscript, can start from the repository alone. That includes the united 10x methylation table from step 05 (gzipped), which is the input to all downstream steps.

Larger intermediates (the model fits of step 05) are written under `04_output/<step>/cache/`, which is git-ignored. Step 05 reuses a cached fit only while what it was made from is unchanged (the mode and the coverage settings, the sample sheet, the coverage files, the methylKit version and the fitting code) and fits again otherwise, or when a cache file cannot be read; nothing has to be deleted by hand.

## File naming

Outputs that depend on an analysis mode carry the mode in the file name, for example `dml_ploidy_legacy.csv` and `dml_ploidy_corrected.csv`. The modes are defined in `run_config.R` and described in `07_documentation/reproducibility_plan.md`, section 4.

`shared` in a file name is the set the draft calls interaction-DML: the loci that are in both the ploidy and the heat list (issue I-02).

Step 05 takes its DML lists and its counts by threshold as methylKit does, with `abs(meth.diff) > threshold` on the unrounded difference. The tables are written with 15 significant digits, so a count retaken from a written table can differ where a difference equals the threshold in the counts and is held one rounding error away from it: `diffmeth_heat_legacy.csv.gz` gives 5,908 loci above 15 points where `dml_counts_by_threshold_legacy.csv` and the legacy script have 5,910, and 2,352 loci of at least 20 points where there are 2,351 DML (corrected mode: 5,669 against 5,671, and 2,274 against 2,273). Three loci are concerned; the header of `01_pipeline/05_differential_methylation.R` names them with their written and their held values. With `>` at the configured 20 points the written tables give exactly the DML lists.

`cpg_counts_by_feature_track.csv` of step 04 exists to trace the genomic distribution of Results 3.1 (issue I-15). Column `legacy_share_pct` divides the overlap count of a track by the sum of the counts of eight tracks, as step 07 does; `legacy_share_exon_twice_pct` first adds the count of the exon track to that of the UTR track, as the legacy workbook did. The eight percentages of the draft are those of one row group only: legacy mode, the ten heat libraries, 10 reads in every library, second column. The header of `01_pipeline/04_cpg_coverage.R` says what they match and what they do not. The track `TE` and the column `track_label` are as described for step 07 below.

In the outputs of steps 06 and 07, `hyper` and `hypo` are the sign of the difference of the list: triploid minus diploid for ploidy, heat minus control for heat. A locus in both lists has two differences, and where it is counted as hyper or hypo the sign is that of its heat difference alone: columns `shared_hyper` and `shared_hypo` of `dml_by_linkage_group_<mode>.csv`, `n_hyper` and `n_hypo` of the set `shared` in `dml_regions_<mode>.csv`, and the series "both lists" of Figure 2B. These are not the classes of those loci (both hyper, both hypo, opposite), which are in `dml_shared_<mode>.csv` of step 05 and are the sets `shared, both hyper`, `shared, both hypo` and `shared, opposite` of step 07. In legacy mode 106 of the 200 loci have a positive heat difference, and 28 are positive in both contrasts.

In the tables of step 07 the track `TE` is the RepeatMasker output of the assembly: repeats of every class, simple repeats included, not transposable elements alone, with 1-based coordinates that are read as a BED file, as the legacy analysis read them. The reading is kept in both modes because the numbers of the draft come from it; it puts 101 of the 480,579 analysed CpGs of legacy mode outside the track. The column `track_label` says what each track holds, and [`03_input_files/genome_features/README.md`](../03_input_files/genome_features/README.md) has the details. The class `other` of `feature_class_exclusive_<mode>.csv` is the mitochondrial CpGs, which lie in no track.

PDF figures and `session_info.txt` carry a time stamp, so they show as changed after a rerun even when the content is the same. The plain CSV files and the PNG figures do not: a rerun on the same machine writes the same bytes. For the tables three things keep it so across machines and users. `write_table()` (`02_R_functions/logging.R`) fixes the line ending (LF) and the notation of numbers, which `fwrite()` would otherwise take from the operating system and from the options of the R session; `run_config.R` sets the options that decide how R turns a number into text; and `.gitattributes` keeps git from converting line endings. Two limits remain:

- A gzipped table (`.csv.gz`, `.tsv.gz`) is identical only when written on the same operating system, because the gzip header records the system (Linux here). On Windows or macOS compare the decompressed content.
- `01_fetch_inputs/tables/input_inventory.csv` records the size and md5 of every file under `03_input_files/` and changes whenever one of them is edited, a README included. Rerun step 01 and commit the table with the edit.
